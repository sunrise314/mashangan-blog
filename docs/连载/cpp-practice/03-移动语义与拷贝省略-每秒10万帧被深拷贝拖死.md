# C++ 语言实战（三）：移动语义与拷贝省略——每秒 10 万帧被深拷贝拖死

前两章的网关只干一件事：200 路慢变量，100ms 一拍，C++ 版闲得 CPU 只有 6%。真正把它压垮的是产线二期：新增 50 路高频振动通道，采样率 2kHz——每秒 10 万个采样点涌进网关。CPU 从 6% 飙到 90%，节拍开始出现毛刺。这一章的事故，主角不是某个函数写错了，而是一类**整个团队都习以为常的「按值传递」**：每一帧数据在到达出口的路上，被拷贝了十几次。

## 一、事故现场：一个 string 引发的 malloc 风暴

先看数据结构，这是埋雷的地方：

```cpp
struct Sample {
    std::string name;   // 信号名，如 "oven_zone3_temp"
    double      value;  // 采样值
    int64_t     ts;     // 时间戳
};
using Frame = std::vector<Sample>;   // 一帧 = 一个通道的一批采样
```

而分发层是这么写的——每个出口（消息队列、本地缓存、调试订阅者）都拿到一份「自己的」帧：

```cpp
void Dispatcher::broadcast(Frame frame) {          // 按值：进来先拷一份
    for (auto& out : outputs_) {
        out->deliver(frame);                       // 部分出口内部再拷
    }
    recent_.push_back(std::move(frame));           // 存最近帧
}

Frame Collector::read_channel(int ch) {
    Frame frame;
    for (auto& s : raw_buffer) {
        Sample smp;
        smp.name  = signal_name(ch, s.idx);        // 每个样本都构造一次 string
        smp.value = s.value;
        smp.ts    = s.ts;
        frame.push_back(smp);                      // 扩容时还要整体搬家
    }
    return frame;
}
```

算一笔账就明白 CPU 为什么烧起来了：振动通道每秒 10 万个 `Sample`，每个 `Sample` 构造都要为 `name` 做一次字符串分配；分发 5 个出口、平均再拷 3 手，同一个字符串在内存里被 malloc/memcpy 十几遍。每秒几十万次小对象分配，glibc 的 malloc 虽快，也扛不住这个频率——分配器锁、缓存失效、页错误全部抬头，90% 的 CPU 里，真正「干活」的还不到两成。

最讽刺的是：这些信号名从头到尾没变过。200 个通道的名字是启动时读配置定死的，却在每一个采样点上被无意义地复制着。

## 二、排查过程：perf 三巨头

CPU 型问题比内存泄漏直接得多——它自己会说话。第一步 `perf top` 扫一眼，热点三巨头已经排队报到了：

```text
  21.4%  memcpy
  17.2%  operator new
  12.6%  std::__cxx11::basic_string::_M_construct<char*>
```

memcpy + new + 字符串构造，合计过半——这不是计算密集，是**拷贝密集**。第二步，`perf record -g -p <pid>` 采 30 秒调 `perf report` 看调用链，三条拷贝路径全部现形：

1. `Dispatcher::broadcast(Frame)` 按值传参 → 每次广播整帧深拷贝；
2. `read_channel` 里 `push_back` 触发 `vector` 扩容 → 已有元素整体搬家，搬家时又逐个拷贝 `string`；
3. `read_channel` 返回 `Frame` 走了拷贝——这条最冤，因为编译器本来可以免费送优化。

第三步，火焰图确认宽度占比（宽度 = CPU 时间占比，一眼看出「平顶」在哪），然后每修一处跑一轮 `perf diff`，让每个优化点自己报成绩。这套「perf top 定性 → record/report 定位 → diff 验证」的三段式，适用于所有 C++ CPU 问题，值得整段搬走。

## 三、底层原理：值类别、移动与编译器的免费午餐

### 左值、右值与移动的本质

C++11 起，表达式分左右值：**左值有名字、能取地址；右值是临时的、马上要消失的**。移动语义的全部思想一句话讲完：**既然右值马上要死，把它肚子里的资源直接偷过来，别傻乎乎地深拷贝**。对 `std::string`，移动 = 换一下内部指针（2ns），拷贝 = malloc + memcpy 整段字符（几十 ns）——差一个数量级起。

实现载体是右值引用 `T&&` 和「移动构造/移动赋值」这对特殊成员函数。关键认知：**`std::move(x)` 本身不移动任何东西**，它只是一次类型转换，把 x 标记成右值，说「我允许你偷我」；真正干活的是被选中的移动构造函数。与之配套的 `std::forward` 用于模板转发场景：保持实参原本的左右值属性原样传下去（完美转发），这是写泛型层（比如第 04 章的驱动工厂）时的标配。

### 编译器的免费午餐：RVO 与 copy elision

比移动更快的，是不拷贝也不移动。函数按值返回一个局部对象时，编译器可以直接在调用方的接收位置上构造这个对象——返回值优化（RVO）。C++17 把纯右值场景的省略定成了**强制**：`return Frame{...}` 连移动构造都不需要有。有名字的局部对象（NRVO）虽非强制，但主流编译器在简单场景都会做。由此得出本章最反直觉的写法守则：

```cpp
Frame read_channel(int ch) {
    Frame frame;
    /* ...填充... */
    return frame;              // 对：NRVO，直接在调用方构造
    // return std::move(frame); // 错：反而抑制 NRVO，多此一举
}
```

`std::move` 一个局部返回值，是 C++ 圈流传最广的「好心办坏事」。

### 五件套与 noexcept 的隐藏条款

每个类有五个特殊成员函数：析构、拷贝构造/赋值、移动构造/赋值。规则和陷阱各一个：**声明了其中任何一个（哪怕只是自定义析构），移动操作就不再自动生成**——很多老代码定义了析构函数，从此它的 vector 扩容悄悄退回全量拷贝，性能莫名其妙掉一半。另一个隐藏条款在 `vector` 扩容：为保异常安全，元素搬家时**只有移动构造标了 `noexcept`，才用移动；否则退回拷贝**。所以「移动构造 + noexcept」要当成肌肉记忆一起写：`Sample(Sample&&) noexcept = default;`。

## 四、正确姿势：元数据下沉，数据单拷贝

重构分三层，按收益排序：

第一层，也是工业软件的正解——**元数据与数据分离**。信号名根本不该跟着采样点跑：

```cpp
struct Sample {
    uint16_t sig_id;    // 信号在元数据表里的下标，2 字节
    double   value;
    int64_t  ts;
};                       // 不再有 string：Sample 变成 16 字节 POD
```

信号名只在出口层按 `sig_id` 查一次表。每帧的 200 次字符串构造直接归零，`Sample` 从 56 字节缩到 16 字节，还天然缓存友好。这一招叫「消除拷贝的最好办法是让拷贝的对象不存在」。

第二层，管住剩下的每一次拷贝：

```cpp
void Dispatcher::broadcast(const Frame& frame) {   // 只读：const 引用
    for (auto& out : outputs_) out->deliver(frame);
}
void Dispatcher::archive(Frame frame) {            // 需要独占：按值 + 调用方 move
    recent_.push_back(std::move(frame));
}
// 调用：dispatcher.archive(std::move(frame));      // 资源转移，零深拷贝
frame.reserve(expected_count);                     // 预留容量，消灭扩容搬家
```

第三层，五件套按 rule of five 补齐并标 noexcept，让 vector 扩容敢走移动。高速振动通道的缓冲同样按此重构——它现在的互斥锁版本在 ch07 还要再进化一次，这是后话。

## 六、面试怎么答

**Q1：std::move 做了什么？**
三句话：它只是 `static_cast<T&&>`，一次类型转换，零运行时开销；它不移动任何东西，只是把实参标记为右值，授予被调方「偷资源」的资格；真正决定偷不偷的是移动构造/赋值是否存在。能主动补一句「move 完的对象处于有效但未定义状态，别再读它的值」，说明真用过。

**Q2：什么是 RVO？C++17 有什么变化？**
按值返回局部对象时，编译器直接在调用方接收处构造对象，拷贝和移动都省掉。C++17 把纯右值返回的省略定为强制语义（拷贝构造甚至可以不存在）；NRVO 非强制。加分项：指出 `return std::move(local)` 是反模式，会抑制 NRVO。

**Q3：vector 扩容时为什么移动构造必须 noexcept？**
vector 扩容搬家要保证强异常安全：搬家途中一旦抛异常，原容器必须完好。移动是「破坏性」操作（源被掏空），如果搬一半抛了，原数据已损——所以只有标了 noexcept 的移动才敢用，否则退回拷贝。这一题是从「背概念」跨到「读过实现」的分水岭。

**Q4：写一个类，特殊成员函数注意什么？**
rule of five + rule of zero 一起答：需要自定义任一析构/拷贝/移动，就该五件套想全；能用 default 就 default；移动操作必须 noexcept；大多数数据类直接 rule of zero（成员自己会管自己）。补一句「声明析构会抑制移动的隐式生成」就是记忆点。

## 七、落地清单

- 值类型里不放 string/容器等重资源成员，能用 id/int 代替的元数据一律下沉
- 只读传 const&，独占转移按值传 + 调用方 std::move，工厂返回 unique_ptr
- 按值返回局部对象直接 return，禁止 return std::move(local)
- 容器能预估长度就 reserve
- 自定义析构的类检查五件套，移动构造/赋值必须 noexcept
- CPU 问题三板斧：perf top 定性、perf record -g 定位、perf diff 验证每一步
